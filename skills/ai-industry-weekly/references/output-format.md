> **编者注**：文中的「46 行」以 `assets/universe.json` 的实际标的数为准。

## 输出格式（以下四节**全部**要写进运行结果正文，缺一节即未完成）

### 📅 产业表周更 | <数据日期 YYYY-MM-DD>

### 🔀 本周变动摘要
- 逐条列出评级有变的标的：<CODE> <旧评级>→<新评级>：<一句原因（基于本周基本面变化）>
- 若全部无变动，写「本周评级无变动」
- 另列关键数据漂移（即使评级没变）：如估值大幅变化、由盈转亏/扭亏、距52周高点显著回落、新卡/退出某瓶颈、临近财报等

### 📋 更新后的完整产业表（直接粘贴用）
用和基准表完全相同的列结构输出全 46 行，包在下面标记之间：
<<<产业表开始>>>
| 代码 | 主题 | 8层 | 瓶颈 | 评级 | 论点 | 估值性格 |
（...全 46 行...）
<<<产业表结束>>>
（若表内含 L8 太空股，在结束标记后另起一段附 SpaceX/Starlink 曝险提醒一句。）

**🚫 本节硬性要求（不得违反）：**
1. **必须在运行结果正文中逐行完整写出全 46 行**，含 `<<<产业表开始>>>` / `<<<产业表结束>>>` 两个标记；标记之间的内容要能被原样复制去更新日报任务。
2. **禁止**用「见 Slack thread」「已推送至频道」「同上」「（略）」「…其余同前」「表格见附件/文件」等任何形式**代替或省略**整表；也**禁止**只列有变动的行。
3. **即使内容长、即使刚刚已推送 Slack、即使本周评级无变动，也必须完整重贴 46 行**。表长不是省略的理由；上下文紧张时优先保证本节完整，其余各节可精简。
4. 只写 46 行本身，不额外加序号列、不改列序、不改列名。行序与基准表一致，便于逐行 diff。

### ✅ 应用方法
把上表替换日报任务（引用本表的那个 routine）「第一步：产业质量参考表」里的表格，并把「最近更新」日期改为今天。或直接对 Claude 说一句「用最新产业表更新日报任务」，把 <<<产业表开始>>>...<<<产业表结束>>> 之间的内容贴给它即可。

# 第四步：推送到 Slack（分两条，第二条走 thread）

**执行顺序：先按「输出格式」把 ①②③ 完整写进运行结果，再做本步推送。Slack 推送是「另外再发一份」，绝不取代运行结果里的整表输出。**

分析完成后，用 Slack MCP 的 `slack_send_message` 把结果推送到频道 **`$NOTIFICATION_SLACK_CHANNEL_ID`**（channel_id 取自该环境变量）。**固定分两条，且第二条作为第一条的 thread 回复**：
- **第一条（发到频道）**：标题 + 变动摘要 + 关键数据漂移。
  1. 标题：`📅 AI算力产业表周更 | <数据日期 YYYY-MM-DD>`
  2. 🔀 本周变动摘要：评级有变的标的逐条；全无变动则写「本周评级无变动」
  3. 关键数据漂移 3–5 条（估值/盈亏/距高点/瓶颈/临近财报等）
  发送后，**记下返回的 `message_ts`**。
- **第二条（发到第一条的 thread）**：完整 46 行产业表（<<<产业表开始>>>…<<<产业表结束>>> 之间内容，用 Slack Markdown 表格）+ 结尾 L8 太空/SpaceX 曝险提醒 + 「仅研究框架，不构成投资建议」。
  调用 `slack_send_message` 时把 `thread_ts` 设为第一条的 `message_ts`（**不要** 勾选 reply_broadcast，保持频道整洁——表只在 thread 内）。
- 说明：不再拆分「表过长」的判断，本任务**固定两条**（第一条摘要在频道、第二条整表在 thread）。若整表仍超过单条 5000 字上限，可把第二条再拆成多条 thread 回复（都挂在同一 `message_ts` 下）。**注意：Slack 单条字数上限只影响 Slack 分条方式，运行结果正文不受此限、必须一次完整输出 46 行。**
- 推送成功后把两条消息链接都回报给用户（附在运行结果末尾，位置在整表之后）。

# 第五步：交付前自检（逐条确认后才算完成）
在结束本次运行前，逐项核对，任一项为「否」就补齐后再结束：
1. [ ] 运行结果正文里有 `<<<产业表开始>>>` 与 `<<<产业表结束>>>` 两个标记吗？
2. [ ] 两个标记之间**实际数出来**是 46 行数据行（不含表头与分隔行）吗？
3. [ ] 表内代码集合与 `assets/universe.json` 的 `tickers` 完全一致（不多、不少、不重、行序相同）吗？（`baseline.py validate` 会替你查这一条；原文此处写的「第一步 T 列表」已非真相源）
4. [ ] 变动摘要里每一条评级变动都有本周基本面依据，且与表内评级一致吗？
5. [ ] 数据缺失处写的是 N/A，没有任何估算或编造数字吗？
6. [ ] Slack 两条（摘要 + thread 整表）都已发送，链接已附在运行结果末尾吗？
7. [ ] 有没有出现「详见 Slack」之类代替整表的写法？若有，删掉并补上整表。
