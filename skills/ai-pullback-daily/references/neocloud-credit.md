# 第二步之四：Neocloud 信用层监控【引爆点④ 的量化层 · 每日必跑 · 脚本取数】

> **定位**：引爆点④ 原本只有定性口径（「利差走阔至困境水平」），实际执行时最难的两件事是——**多少 bp 算困境？走阔了究竟是 neocloud 自己的问题，还是全市场的问题？** 本节把④拆成**四层可复现的量化判定**，由脚本 `neocloud_credit_monitor.py` 每日取数产出，替代人工判读；④的最终 🟢/🟡/🔴/⚪ 由脚本按下方规则算出，日报直接引用。
>
> **为什么必须拆层（本节最重要的结构性发现）**：同一个赛道、同一类资产，信用市场的定价可以差近 4 倍——**项目层**（投资级租户长约的 SPV 债，如 Cipher 的 AWS 租约 SPV「Black Pearl」）与**公司层**（发行人无担保债，如 CoreWeave 公司债）之间存在数百 bp 的裂口。市场早就不买「AI 数据中心」这个标签，而是在给**租户信用**定价。因此两者含义完全不同：
> - **公司层利差走阔** = neocloud 融资成本上升、股权稀释加剧 → **主题仍在，只是股东变贵**（节奏问题，归第二步之三处理）
> - **项目层（投资级租户）利差走阔** = AI 算力现金流本身被质疑 → **这才是主题崩坏**（论点问题，走步骤3 宏观闸门）
>
> 把两者混成一格，就会把「股东被稀释」误判成「论点破」，在质量最高的买点上关掉买入桶——这与「第二步之三」要防的错误同源。
>
> **为什么不能用 HYG/JNK 监控本主题**：宽基 HY ETF 与 neocloud 已完全脱钩（实测 HY 指数 OAS 30日仅 +7bp、HYG 月变动 −0.6%，而 neocloud 股票同期 −9% 至 −31%）。对应读数在 **CCC 尾部**（同期 90日 +104bp）与**个股债券自身报价**，宽基指数会把它整个掩盖掉。
>
> **运行频率**：每个日历日都跑（与引爆点监控同频）。指数与曲线是日频官方数据，休市日沿用最近发布值并标注数据日。
>
> **与 NCLD（Roundhill Neocloud ETF）的联动**：本节的信用层是产业表内 NCLD 一行的**领先指标**——NCLD 前五大（Nebius/CoreWeave/IREN/Hut 8/TeraWulf）中，CoreWeave 与 IREN 已在 `neocloud_bonds.json` 的发行人名单内。公司层利差走阔 → NCLD 股东被稀释（节奏问题）；**项目层（投资级租户 SPV）利差走阔 → NCLD 的论点本身被质疑**，此时产业表内 NCLD 应维持 🟡 并考虑 🔴。反向亦成立：信用层健康时，NCLD 的 🟡 只是「新上市＋高波动」的技术性压评。

**执行方式（脚本，非 WebSearch）**：
```bash
python3 neocloud_credit_monitor.py              # markdown，直接贴进完整版
python3 neocloud_credit_monitor.py --compact    # 精简版一行（Slack 用）
python3 neocloud_credit_monitor.py --json       # 机读
```
- **自动取数（免 key）**：FRED CSV 端点取信用指数 OAS（`BAMLH0A0HYM2` HY／`BAMLH0A1HYBB` BB／`BAMLH0A2HYB` Single-B／`BAMLH0A3HYC` CCC／`BAMLC0A0CM` IG／`BAMLC0A4CBBB` BBB／`BAMLHE00EHYIOAS` EUR HY）、美债曲线（`DGS2/3/5/7/10`）、`SOFR`、`VIXCLS`；yfinance 取信用/杠杆贷款 ETF（HYG·JNK·LQD·ANGL·**BKLN·SRLN**）与 neocloud 个股（CRWV·NBIS·IREN·APLD·WULF·CIFR·GLXY·DTCR）＋基准（NVDA·SMH·QQQ）。
- **半自动取数（须人工/WebSearch 喂）**：**个股债券报价没有免费 API**。流程 = 日报的 WebSearch 步骤取到价格 → 填进 `neocloud_bonds.json` 的 `quote.price` + `quote.as_of` + `quote.source` → 脚本自己反解 YTM（半年付息，**折现全价 = 干净价 + 应计利息**；par 债不变量残差 <1bp，到期日仅知月份时按当月 15 日另有约 ±3bp 口径误差）并对 DGS 曲线插值算利差。**应计利息不可省**——早期版本拿干净价直接比对折现值，把 YTM 高估最多约 70bp（偏差随距下次付息远近变化），足以虚假触发 L1。`quote.as_of` 超过 `--max-quote-age`（默认 5 天）的债券判 ⚪、**不参与触发判定**（不把旧价当新价）。
- **历史档 `neocloud_credit_history.jsonl`**：每日一笔（同日重跑覆盖），供①相对基准的**变化率**检验、②「状态是否跨档变化」侦测。脚本输出末尾的「⑩ 跨档变化」即为此。
- **一级市场条款**写进 `neocloud_bonds.json` 的 `primary_market.deals`；脚本按 SOFR 折算**全包成本**（含 OID 按 3 年寿命摊销），这是 L1 里信息含量最高的一项——**发行人被迫让价 ≠ 二级指数缓慢漂移**。
- **定性开关**写进 `manual_flags`（一级市场交易被撤回/延期、hyperscaler capex 下修、有 CDS 数据源时的 CDS 值）；**没有可靠新证据就留 `null`，不猜**。

**建立基线时的读数（2026-07-30，供日后校准对照）**：L1 公司层基准债 **545bp**（同评级溢价 +242bp）→🟢；L1 一级市场重定价 **+125bp 利差 / +209bp 全包成本**（S+425→S+550、OID 99→96.5，SOFR 3.65%）→🟡；L2 项目层 **146bp**（价 101.28）→🟢；L3 HY OAS 2.87%、CCC 10.13%（90日 +104bp）、**CCC−BB 837bp**→🟡；L4 NVDA 距高点 −18.0%→🟢。**④ 汇总 = 🟡**。注意：L1 的两项二级读数（545 vs 阈值 600、242 vs 阈值 250）都**只差一点就跨档**，小幅走阔即会翻🟡——这也说明当前 L1 的🟡完全来自一级市场被迫让价，二级市场尚未确认。

> 编者注（**表内缺的一条：L1 一级市场 30 天观察窗**）：上表声明「脚本 `TH` 字典即此表」，但脚本的 `TH`
> 另有一条本表未列的参数 —— `L1_primary_window_days = 30`（`neocloud_credit_monitor.py` 与
> `neocloud_credit_lite.py` 两份 `TH` 里都有，须同步）。含义：**「一级市场单笔重定价幅度 ≥ +100bp → 🟡」
> 只在该笔交易成交后 30 天内计入 L1 判定**；超过 30 天的最近一笔记为「**仅历史参照，不计入判定**」，
> 脚本会在 L1 明细里写出成交距今天数与「超出 30 天观察窗」。
>
> 为什么要有它：一级市场是**事件**而非**连续报价**，没有窗口的话，一笔半年前的被迫让价会把 L1 永久钉在 🟡，
> 该指标就此失效。代价是**这条规则会改变引爆点④ 的汇总输出**——窗口一过，若二级读数仍在阈值内，
> **L1 由 🟡 落回二级读数单独决定的状态**——二级报价新鲜且在阈值内则为 🟢，二级报价过期／缺失
> 则 l1_states 为空、L1 落 **⚪**（本仓库随附的种子报价即属后者）。④ 的汇总可能随之变化。
> 这不是行情变好，是那笔交易过期出窗；
> 日报出现这种跨档时须在完整版点明原因，不得当作信用面改善来解读（脚本第⑩块「跨档变化」会给出提示）。
> 「建立基线时的读数」一段里那个来自一级市场的 🟡，也须按此窗口理解。

- ★ **L2 与 L4 才是真正该盯的**。L1/L3 衡量的是「股东被稀释多少」与「全市场风险偏好」，**不是「AI 算力需求是否见顶」**。L1/L3 先动是常态，不构成论点受损。
- 转债（如 IREN 的两笔）利差含期权价值，**不可直读为纯信用利差**，脚本一律标「仅参考」、不参与任何判定。EUR 计价债不对美债曲线，只对 EUR HY 指数做相对比较，绝对利差标 N/A。

**引爆点④ 最终状态的映射规则（脚本自动执行，按优先级）**：
1. **论点侧**（L2 或 L4）出现 🔴 → **④ = 🔴**（项目层/上游已破，走步骤3 宏观闸门）。
2. **融资侧**（L1 或 L3）达 🔴，但相对基准检验判「**宏观**」→ **④ = 🟡**（与 HY 基准同步，归第二步之三驱动源处理，**不走论点闸门**）。
3. 相对基准检验判「**无法区分**」（缺 HY 基准或缺 neocloud 利差）→ **④ 封顶 🟡，不得升🔴**（沿用原「引爆点④ 的 Fed 传导校准」硬规则）。
4. 融资侧达 🔴 且相对基准检验判「**个体**」→ **④ = 🔴**（个体融资链问题）。
5. 其余 → ④ = 融资侧与论点侧中的较严重者；四层皆 🟢 → ④ = 🟢；全无可用数据 → ④ = ⚪ 沿用上次状态。

**相对基准检验的两种口径（脚本自动选择）**：
- **变化率法（优先，需历史档 ≥30 日）**：`超额走阔 = neocloud 基准债利差30日变化 − HY OAS 30日变化`；≥ +50bp → 判「个体」，否则判「宏观」。
- **水平法（历史档不足时的替代）**：直接看**同评级指数溢价**（公司层利差 − Single-B OAS）是否 > 250bp。这一口径不需要历史即可用，且分母是**同评级同侪**而非全 HY，比宽基比较更干净。脚本会注明用的是哪一种。

**并入综合分析的规则（硬约束）**：
1. **④的状态只由本节产出**，日报「🧭 引爆点监控」表第④行直接引用脚本输出的第⑨块，不另行人工判读、不与脚本结论冲突。
2. **L2/L4 → 论点闸门（步骤3）**；**L1/L3 → 节奏层（步骤4）**，与第二步之三的驱动源叠加、取更保守者。**L1/L3 单独走阔不得降级任何买入桶**——这与「① 折现率驱动不得降桶」是同一条红线。
3. 当出现「L1/L3 已动、L2/L4 未破」（即脚本裁决为「🟡 可买的回撤（限定在融资成本这条腿）」）→ 完整版须明确写出**这是股东稀释成本上升、不是需求见顶**，并在节奏上体现：涉及 neocloud 融资链的标的（本监控池中最相关者为 **NVDA**，其订单簿依赖 neocloud 融资能力）首批仓位按驱动源规则处理，其余照常。
4. **股债背离的方向判读**：股票端跌幅远大于债券利差走阔时，须给出方向结论——若一级市场刚发生 ≥100bp 的被迫让价，判「**债券在跟上、不是在否认**」（信用市场滞后）；若一级市场无重定价、二级利差稳、股票单边跌，判「**股票超跌**」。这一句写进「💡 总结与前瞻」。
5. **缺数据不得推高结论**：脚本的 ⚪ 不参与升档；「⑧ 数据缺口」整段照原样贴入完整版，不得省略。

**已知数据局限（每次输出须保留声明）**：
① 债券报价来自挂牌/终端报价，成交稀薄，与 TRACE 实际成交可能差数十 bp；② **无实时 CDS 数据是本层最大盲区**——CoreWeave 5y CDS 是本主题最干净的单一指标，有 Bloomberg/Markit 数据源时填入 `manual_flags.cds_5y_bp`，L1 判定即改用 CDS 基准；③ EUR 债利差应对 Bund，脚本只做 EUR HY 相对比较；④ 转债利差含期权价值；⑤ 样本以 CoreWeave 为主（公司层）＋ Black Pearl（项目层），其余 neocloud 的公司债二级报价未取到，结论对 CoreWeave 敞口偏重。
