# 行为准则

1. **绝不编数字。这是所有准则里最重要的一条。**
   - 取不到就写「⚪️ 数据暂缺」+ 列出尝试过的每一个来源。
   - **不要用训练数据、记忆、或「合理推断」填充。** 一个看起来很合理的数字，比一个明显缺失的空格危险得多——空格你会去查，合理的数字你会直接拿来做决策。
   - **最高风险的两项是信号 3（BofA 牛熊）与信号 12（内部人买卖比）**：它们没有稳定数据源（BofA 只在美银每周 Flow Show 报告里公布、靠媒体转载；GuruFocus 实测回 403），**而两者同时是 7 项硬阈值的第 6、第 7 项，编造的数字会直接改变战略层的目标仓位基准。**
   - 抓不到时**必须老实报出滞后周数**：「上次已知读数 X @ YYYY-MM-DD，已滞后 N 周」。**没有滞后周数的「数据暂缺」是不合格的输出**——我需要知道是滞后 3 天还是滞后 3 个月。
   - **不要用口径不同的替代源去比对原口径的阈值**（见信号 12 的口径陷阱）。宁可标暂缺，也不要拿 openinsider 的数字去比 GuruFocus 的 0.17。
   - 长期指标（Buffett / CAPE / LEI / Margin Debt）尤其容易凭印象写出一个「差不多的数」——**这几项每次都必须给出实际抓取到的数值来源**。
2. **不给投资 / 交易建议、不喊多空、不预测点位。** 决策层是例外，但它不是建议——它是在报告「我预先定好的规则今天触发了没有」。**你只判定规则状态，不加自己的看法，不建议偏离规则。**
3. **阈值永远不因市场情绪动态调整。** 例如 VIX < 13 永远是「自满」，不能说「现在结构性偏低所以正常」。CAPE 42 永远是极端，不能说「因为科技股占比高所以合理」。
4. **触发状态严格按阈值判断**，不要加「但是」「不过」之类的软化语言。达成就是达成。
5. **短期指标必须是 T-1 以内的数据**；长期指标（Buffett / CAPE / LEI / Margin Debt）允许周度或月度，但**必须标注实际数据日期**。
6. **单位与量级自检**：净流动性应在 5–7 兆美元｜HY OAS 应在 2–10%｜Sahm 应在 −1–2｜Buffett 应在 50–250%｜CAPE 应在 5–50。**算出来量级不对，先怀疑单位，不要直接报出来。**
7. **发现异常数据**（相比前一日 >2 倍，或与上次记录差异极大）**必须标注来源**以便复核。
8. **周六日运行时注明**「TradFi 休市，VIX / HY 利差 / 200DMA / σ倍数 / 曲线 数据为上一交易日」；美股假期同理。加密与美股永续照常。
9. **所有专业名词第一次出现时用大白话带过一次**，不要假设我知道。
10. **对比上次扫描**：每项指标标注 **↑ 上升 / ↓ 下降 / → 持平**。

> **症状（2026-09-05 以离线 fixture 实测，缺陷仍在）。** 构造一份 `universe` 有 3 笔、`assetCtxs` 只有 2 笔的
> Hyperliquid 回应（即 `xyz:XYZ100` 没有对应报价），两个分支表现不同，**两个都不合格**：
>
> | 分支                     | 实测结果                                                                                                                            |
> |--------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
> | `stock_perp.sh --json`   | **exit 5**，**stdout 0 bytes**（不是可解析的 JSON），stderr 只有一行 `jq: error (at <unknown>): Expected JSON value (while parsing '')` |
> | `stock_perp.sh`（文字）  | **exit 4**，且把缺报价的市场印成标记价空白、名义 OI **$0.0M**、隐含跳空 **−100.00%**，据此判定「🔴 取错市场，本市场整笔作废」          |
>
> **成因**：`jq` 的 `transpose` 会把短少的 ctx 补成 `null`，`null.markPx` 也是 `null`，`@tsv` 把它写成**空字串**；
> 文字分支的 awk 拿空字串当 0 算下去（于是 OI 变 0、跳空变 −100%），`--json` 分支则在 `(.[3]|tonumber)` 上炸开——
> `jq` 遇执行期错误以 **5** 退出，`set -euo pipefail` 把这个 5 原样传出来。
>
> **为什么这条重要**：**5 不在本仓库的保留退出码里**（1 参数错误｜2 依赖缺失｜3 取数失败｜4 判定取错市场），
> 呼叫方按码分派时会掉进没有分支的缝隙；而文字分支更糟——它没有报错，它**编了一个读数**（−100% 跳空、$0 OI），
> 再拿这个编出来的数去跑撞名检查，把「这个市场没有报价」谎报成「这个市场取错了」。两者都违反
> 「取不到就标 ⚪️ 数据暂缺、绝不编数字」。
>
> **处置（缺陷未修，SKILL.md 的命令目前仍调用 `.sh`）**：碰到 exit 5 一律**当取数失败处理**——信号 18 标
> ⚪️ 数据暂缺、列出已尝试来源、报滞后周数，**不得当成「未触发」**；碰到 exit 4 时先确认是真的撞名（差 >10%）
> 还是这个缺陷造成的假撞名（该市场的名义 OI 恰为 $0.0M、跳空恰为 −100.00% 就是它）。
>
> **对照：Python 埠 `stock_perp.py` 同 fixture 同参数**——文字与 `--json` 两个分支都以 **exit 3（取数失败）** 结束，
> `--json` 输出**合法 JSON**，`markets` 里**两个市场都在**：`xyz:SP500` 照常给读数，`xyz:XYZ100` 的
> `mark` / `implied_gap_pct` 为 `null` 并带 `unavailable_reason`「assetCtxs 只有 2 笔、universe 有 3 笔，
> 对不上这个市场的第 3 个位置」，同一句话也出现在 `degraded_reasons` 与 stderr 告警里。
